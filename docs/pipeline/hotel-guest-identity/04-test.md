### 2. Analysis of Duplication Risks
We evaluated the risk of presenting redundant guest-identity boxes, particularly in states where the parent admission data is loading, missing, or faulted.

*   **The Conditional Isolation in Card Blocks**:
    In `HotelAdmissionPolicy.tsx`, the `HotelAdmissionPolicyCardBlock` renders `Body` (which conditionally places `HotelGuestIdentityRules` when state is `'reported'`). If the parent state is `'loading'`, `'error'`, or `'not_provided'`, the inline mapper is bypassed, and the outer container renders the identity rules via:
    ```tsx
    {presentation.state !== 'reported' ? (
      <div className="mt-3">
        <HotelGuestIdentityRules ... />
      </div>
    ) : null}
    ```
    This structural bifurcation guarantees that the identity rule card is **never rendered twice** in a single card block, regardless of state transition.
*   **Page-level Isolation in Booking Flow**:
    In `BookingFlow.tsx`, the summary-deck render (`HotelDecisionSummary`) explicitly disables the nested identity module by passing `includeIdentityRules={false}`. This ensures the user does not see redundant check-in ID disclosures on the initial decision page while reserving the full interactive presentation layout (`HotelGuestIdentityRules`) for the final handoff screen (`HotelHandoffReview`).
